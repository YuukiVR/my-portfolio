Overview

A gallery that grows by dropping in photos.

AcoustiPads Services needed a simple public gallery for completed vehicle soundproofing installations. Visitors should be able to find work by vehicle body type — crossover, hatchback, SUV — and browse the photos without wading through a messy folder dump.

I designed and built a lightweight static site: no database, no CMS, no framework. The gallery index is generated automatically from the image folders, so adding a new category or a new batch of photos is as simple as dropping files into the right folder and rebuilding.

The problem

Photos exist. A usable gallery doesn’t.

Installation photos were piling up as raw camera files (HEIC/DNG originals) with no structure. Potential customers had no easy way to see what a finished job looks like for their vehicle type, and updating a hand-coded HTML page for every new photo wouldn’t scale.

  • No way to browse by vehicle type
  • No search — finding one vehicle meant scrolling everything
  • Manual HTML edits for every new photo
  • Heavy originals would make a naive page painfully slow

What I built

Small features, all pulling weight.

01

Live search

A search box in the hero filters categories as you type, so “crossover” or “hatch” jumps straight to the right gallery.

02

Category pages

Each body type gets its own page (category.html) with a photo count and a clean grid — no endless scrolling.

03

Auto-generated catalog

A Node script scans images/<category>/, sorts files numerically, and writes gallery.json. New photos appear automatically.

04

Full-screen lightbox

Click any photo to view it enlarged, with a close button and click-outside-to-close — same pattern as my portfolio lightbox.

05

Performance-minded

Lazy-loaded images, lightweight vanilla JS, and a recommendation to convert HEIC/DNG originals to JPG/WebP before deploying.

06

Zero-cost hosting

Deployed to GitHub Pages via GitHub Actions (npm run build on every push to main), with a Netlify config as an alternative.

How it works

Four steps from camera to website.

  1. 01

    Drop photos in a folder

    Place converted JPG/WebP files in images/crossover/, images/hatchback/, or a new category folder.

  2. 02

    Run the build

    npm run build runs scripts/generate-gallery.js, which regenerates gallery.json with counts and thumbnails.

  3. 03

    Push to main

    GitHub Actions runs the same build in CI and publishes the result to GitHub Pages automatically.

  4. 04

    Visitors browse & search

    The homepage renders categories from gallery.json, search filters them live, and each category opens its own gallery page.

Tech stack

Deliberately boring tech.

Frontend

  • HTML5 — semantic hero, sections, and gallery markup
  • CSS3 — custom stylesheet, Poppins via Google Fonts
  • Vanilla JavaScript — category rendering, search, lightbox
  • gallery.json — single data source for the whole gallery

Build & deploy

  • Node — scripts/generate-gallery.js catalog builder
  • GitHub Pages + GitHub Actions — build & publish on push
  • Netlify — netlify.toml kept as a fallback host
  • .nojekyll — ensures generated files publish as-is

Current state

Live, with room to grow.

The gallery is live today with the Crossover category populated (11 installation photos). Hatchback and SUV categories are already wired up and show “Images coming soon” placeholders — adding photos there requires no code changes, just files + a rebuild.

  • Crossover — 11 photos, live
  • Hatchback — structure ready, awaiting photos
  • SUV — structure ready, awaiting photos

Planned next steps: convert remaining originals to WebP for faster loads, add per-photo captions (vehicle model + work done), and an SEO-friendly description per category.
